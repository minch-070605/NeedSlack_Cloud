# 설계결정 0002 — M3 학습 데이터는 tar 로 묶어 Google Drive 로 옮긴다

- **상태**: 채택 (2026-09-22)
- **영향 범위**: `pipelines/snapshot.py` 의 출력 형식 · M3 Colab 노트북 · `dataset_version`

---

## 1. 맥락

M3 는 Colab 무료 GPU 에서 두 팔 × 3시드를 재학습한다. Colab 은 클라우드에서 돌고 MinIO 는 이 PC 안에
있어서 **Colab 이 번들을 직접 읽을 수 없다.** 그런데 경로가 증명되려면 학습 이미지는 rev.9 폴더가 아니라
**MinIO 번들에서 꺼낸 것**이어야 한다(`edge-agent/replay.py` 머리말).

rev.9 는 같은 문제를 데이터를 tar 로 묶어 Google Drive 에 올리고 Colab 에서 푸는 방식으로 풀었다
(`rev.9/08_이관/build_colab_nb.py` — "새 Drive 레이아웃(tar 3개)").

rev.9 축 2 의 학습 레시피(`rev.9/04_중앙AI/y5_train_eval_axis2.py`, `runs_yolo/axis2/*/args.yaml`):

| | 내용 |
|---|---|
| 시작 가중치 | 0단 base `runs_yolo/ybase/weights/last.pt` (yolov8n) |
| 학습 | 팔이 고른 2,449 프레임 — 시드와 무관하게 같은 목록 |
| val | `frame_index.csv` 의 `tune` 앞 800 — 진행 표시용, 가중치 선택에 쓰지 않는다 |
| 평가 | `held_out` 2,826 — 학습이 끝난 뒤 따로 |
| 인자 | epochs 16 · batch 32 · imgsz 640 · workers 2 · SGD · lr0 0.005 · deterministic · amp 끔 · mosaic 끔 · last.pt |

## 2. 결정

> **스냅샷이 tar 를 두 종류 만든다. 사람이 Drive 에 올리고, Colab 이 풀어 학습한다.**

| tar | 무엇 | 출처 | 몇 개 |
|---|---|---|---|
| `ds-{ARM}.tar` | 학습 이미지 2,449 · 그 라벨 · `manifest.jsonl` · 학습 목록 | 이미지는 **MinIO 번들에서 잘라 sha256 을 다시 대조한 것**. 라벨은 rev.9 nuScenes 정답 | 팔당 1 |
| `eval-common.tar` | val 800 · held-out 2,826 의 이미지·라벨 · `ybase` 가중치 · 목록 | rev.9 산출물 (파이프라인을 지나지 않는 고정 평가셋) | 1 |

- 파이프라인이 실어 나르는 것은 **학습 이미지뿐**이다. 평가셋·라벨·시작 가중치는 두 팔에 똑같이 주는
  고정 자산이라 한 번만 만든다 — 두 팔에 주는 것이 선별 배열 말고 전부 같아야 한다(`docs/작업규칙.md §1`).
- 파일명은 `{frame_id:05d}.jpg` 로 rev.9 와 같게 둔다. 라벨·목록을 frame_id 로 되읽을 수 있다.
- 스냅샷은 tar 를 `data/snapshots/`(커밋하지 않음)에 쓰고, `manifest.jsonl` 과 `snapshot.json` 을 MinIO 버킷
  `ns-datasets` 의 `datasets/ds-{ARM}/` 에 올린다. `dataset_version.manifest_s3_uri` 가 manifest 를 가리키고,
  그 옆 `snapshot.json` 이 manifest · `ds-{ARM}.tar` · `eval-common.tar` 의 sha256 을 담는다.
  Colab 은 풀기 전에 tar 의 sha256 이 이 값과 같은지 확인한다.
- sha256 을 PG 컬럼으로 두지 않는다 — 그러면 스키마 마이그레이션이 되는데, 계보는 manifest URI 한 줄로 이미
  `snapshot.json` 에 닿는다.

## 3. 근거

- **비용 $0 · 새 의존성 없음.** Drive 업로드는 브라우저로 한다. 터널(외부 공개)이나 Colab 전용 SDK 가 필요 없다.
- **경로 증명이 유지된다.** 학습 이미지가 번들에서 잘려 나오고 sha256 이 판정의 값과 대조되므로, 학습에 쓰인
  바이트가 차량이 보낸 바이트와 같음이 tar 안에서 성립한다.
- **rev.9 가 이미 이 방식으로 Colab 학습을 했다.** 노트북·레이아웃의 선례가 있다.

## 4. 귀결

- 스냅샷은 **재생 결과가 rev.9 선별을 정확히 재현했는지**를 먼저 확인한다 — INDEXED 프레임 집합이
  `selections_axis2/{ARM}_mc_rate0.10_s1.npy` 와 같지 않으면 멈춘다. 파이프라인이 대조를 왜곡하지 않았다는
  것(수용 기준 3)의 데이터 쪽 절반이다.
- 학습 프레임 ∩ held-out = ∅ 를 스냅샷이 검사한다(수용 기준 7).
- Drive 업로드는 **사람이 하는 단계**다. 노트북은 tar 의 sha256 이 계보와 다르면 학습을 시작하지 않는다.
- `eval-common.tar` 는 rev.9 산출물을 읽어 만든 사본이다. 저장소에는 들어오지 않는다(`data/` 는 커밋 대상이 아니다).

## 5. 되짚을 조건

- M4 에서 평면 2 를 실제 S3 로 올리면 → Colab 이 S3 를 직접 읽을 수 있으므로 tar 를 거치지 않아도 된다
- Colab 대신 로컬 GPU 로 학습하게 되면 → MinIO 를 직접 읽는다
- Drive 무료 용량(15 GB)이 부족해지면 → tar 를 팔별로 나눠 올리고 내린다 (현재 합계 약 1.6 GB 추정)
